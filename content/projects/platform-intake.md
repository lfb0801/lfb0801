# Platform intake

> Status: active case study

Platform intake is the boundary between a team's need and the platform work that might address it. Designing that boundary well turns requests into evidence for product decisions instead of tickets moving through a queue.

## The problem

A free-form request captures symptoms but rarely the context needed to act. A large mandatory form captures fields but discourages conversation. In both cases, the platform team can become a service desk that accepts solutions before understanding problems.

The intake path must support an engineer who needs help now while also revealing recurring friction worth solving once for many teams.

## Design principles

- **Begin with the problem.** Requested solutions are useful clues, not settled requirements.
- **Ask only decision-changing questions.** Every required field spends attention and should justify that cost.
- **Route by capability and urgency.** Team boundaries should not be knowledge a requester must already possess.
- **Keep status and ownership visible.** A request should never disappear behind an internal hand-off.
- **Feed patterns back into the platform roadmap.** Repeated requests are product evidence, not merely repeated work.

## The collaboration boundary

Intake is not a promise that the platform team will implement every request. It creates a shared place to clarify impact, constraints, alternatives, and ownership. Some requests become platform capabilities, some remain product-specific, and some are resolved by making an existing path easier to discover.

## What I am evaluating

- how quickly a request reaches someone able to make a decision
- how often clarification reveals a different underlying need
- whether requesters can understand status without asking for updates
- which themes recur across teams and repositories
- whether rejected or redirected requests retain a useful rationale

Good intake shortens the distance between platform users and platform decisions without turning either side into a ticket processor.
